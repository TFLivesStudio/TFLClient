TFL CLIENT — CHANGELOG: firma ad-hoc macOS + sistema de auto-actualización (preparado, sin activar)
================================================================================

src-tauri/tauri.conf.json
  + bundle.macOS.signingIdentity: "-" — firma ad-hoc automática en cada
    build (gratis, sin cuenta Apple Developer). Arregla el falso "tflclient
    está dañado y no se puede abrir" que tira Gatekeeper en macOS Sequoia
    cuando el .app no tiene NINGUNA firma y además tiene el atributo de
    cuarentena (que pone el navegador al descargar). No es firma real de
    Developer ID: sigue apareciendo el aviso normal de "desarrollador no
    identificado" la primera vez (clic derecho → Abrir lo resuelve) — eso
    solo desaparece con una cuenta Apple Developer paga ($99/año) +
    notarización, que queda pendiente de infraestructura.
  + plugins.updater: pubkey real (clave pública del par generado para
    firmar actualizaciones) + endpoints con placeholder
    (https://updates.tflclient.invalid/latest.json, dominio reservado
    RFC 2606 que nunca resuelve a propósito) + installMode "passive" en
    Windows. El endpoint real se define cuando se decida dónde hostear
    latest.json — ver sección PENDIENTE.

src-tauri/src/lib.rs
  + Registrado tauri_plugin_updater dentro de .setup(), gateado a
    #[cfg(desktop)] (el updater no aplica a mobile).

src/lib/components/settings/SettingsPanel.svelte

PENDIENTE — para que el sistema de auto-update funcione de verdad
================================================================================
  1. Decidir DÓNDE se hostea latest.json + los instaladores firmados.
     El token default de GitHub Actions de este repo NO puede crear
     Releases (permiso deshabilitado a nivel de la org) — opciones:
       a) Generar un Personal Access Token con scope "repo", agregarlo
          como secret del repo, y usarlo en el workflow para crear
          Releases reales (tauri-action ya soporta esto con
          includeUpdaterJson: true).
       b) Hostear el manifest en otro lado (Cloudflare Pages, S3, etc.)
          con sus propias credenciales como secrets.
  2. Poner la clave PRIVADA (contenido de
     ~/.tauri/tflclient-updater.key) como secret de CI
     (TAURI_SIGNING_PRIVATE_KEY), idealmente regenerada con password
     (TAURI_SIGNING_PRIVATE_KEY_PASSWORD) antes de usarla en producción.
  3. bundle.createUpdaterArtifacts: true en tauri.conf.json (hoy en
     false a propósito, para no romper el build actual sin la clave
     privada en CI).
  4. Reemplazar el endpoint placeholder por la URL real del latest.json.
  5. Actualizar .github/workflows/build.yml para publicar el latest.json
     + los artifacts firmados en el destino elegido en el punto 1.

  Nada de esto se tocó todavía porque necesita una decisión externa
  (dónde hostear, y crear el secret correspondiente) que no puedo tomar
  ni ejecutar solo.
