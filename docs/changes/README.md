# Informes técnicos de cambios

Guarda aquí los informes de trabajo nuevos, por ejemplo
`2026-11-13-descripcion-del-cambio.md`. Utiliza la fecha real y un nombre que
permita reconocer el tema. Conserva cada informe en su ruta y añade la versión
publicada cuando se conozca.

Un informe útil identifica:

- El problema o la función trabajada y los archivos afectados.
- El comportamiento implementado y sus límites.
- Las comprobaciones realizadas y los pendientes.
- La versión o el tag que incorporan el cambio, cuando se publique.

Esta documentación está dirigida al equipo. Las notas para jugadores se escriben
por separado en `docs/releases/<tag>.md` y `src/lib/releaseNotes.ts`, siguiendo la
[guía de publicación](../maintainers/publishing.md).

Los informes originales trasladados de la raíz siguen en
[docs/history/legacy](../history/legacy/). No hace falta modificarlos ni moverlos
otra vez al documentar un cambio nuevo.
