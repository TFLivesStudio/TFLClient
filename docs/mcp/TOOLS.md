## Examples

Read: `tfl_list_instances({"limit":20,"offset":0})` returns an object with total,
offset and summaries keyed by `instance_id`. Use that exact UUID in subsequent calls.
No account UUID or credentials are included.

Change a preference: first `tfl_get_preferences({})`, then
`tfl_set_preference({"key":"style","value":"pixel","expected_revision":0})` with
**the revision actually returned**. Stale revisions fail instead of overwriting.

Content: search using the target UUID, fetch compatible versions, then install an
explicit `project_id`/`version_id` with an idempotency key. No URL is accepted.
`tfl_get_job({"job_id":"<returned UUID>"})` polls the real result; poll at most once
per second to stay within the session rate limit. Running cancellation is refused.

Critical: `tfl_plan_action({"instance_id":"<exact UUID>","action":"delete_instance"})`
returns `plan_id`, `awaiting_local_approval`, and expiry. It does not delete. Only after
a local decision may `tfl_execute_plan({"plan_id":"<returned UUID>"})` enqueue the
exact action. Never invent or reuse approval IDs.

## Results, resources and errors

Successful tool results contain both text JSON and `structuredContent.data`; the
output schema requires the `data` envelope. Business failures are `isError` tool
results, not ambiguous nulls. Validation errors use MCP invalid-params errors. Common
codes: MCP_DISABLED, APPROVAL_REQUIRED, PERMISSION_DENIED, INSTANCE_SCOPE_DENIED,
SESSION_EXPIRED, LOCAL_APPROVAL_REQUIRED, STATE_CHANGED, PREFERENCE_CONFLICT,
IDEMPOTENCY_KEY_CONFLICT, JOB_NOT_FOUND, TOOL_TIMEOUT and SYMLINK_NOT_ALLOWED.

`tfl://capabilities` and `tfl://instances` resources reuse the same approved read
services. No file-backed credential resources are offered. MCP prompts/subscriptions
are not advertised; curated tools/resources are the implemented contract.
